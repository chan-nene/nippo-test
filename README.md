# NIPPO

CSVをデータストアとして利用する、pywebview製の日報デスクトップアプリです。本人の日報入力、チーム内の日報閲覧、担当部下への上司コメントを1つの画面で扱います。

## 必要環境

- Windows
- Python 3.13
- Microsoft Edge WebView2 Runtime

## セットアップ

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python .\main.py
```

初回起動時に設定画面が開きます。日報、上司コメント、共通マスターの各フォルダを指定してください。

`settings.example.ini` は配布用の空ファイルです。実際の `settings.ini` はローカル設定を含むためGit管理しません。

## 管理者機能

共通マスター画面は、`user_master.csv` の `is_admin` が `1` の正社員だけが利用できます。`is_admin` が `1` でも派遣社員は管理者として扱われず、管理APIも処理を拒否します。初回の管理者登録は、運用担当者が `user_master.csv` の該当ユーザーを正社員として登録し、`is_admin` に `1` を設定してください。

## 共通マスターと所属チーム

共通マスターフォルダでは、次の3ファイルを使用します。アプリ内の「共通マスター」画面から、チーム・ユーザー・コメント対象組織を保存できます。

- `team_master.csv`: `team_id,team_name,team_level,parent_team_id,sort_order,is_active`
- `user_master.csv`: `employee_id,display_name,can_input_own_report,employment_type,is_admin,small_team_id,display_order`
- `team_master.csv`: `team_id,team_name,team_level,parent_team_id,sort_order,is_active,commenter_employee_ids`
- `calendar.csv`: `date`

管理画面の稼働日カレンダーは4月1日から翌年3月31日までを1年度として表示します。`calendar.csv` は休日の日付だけを保持し、行がない日付は稼働日として扱います。年度を初めて表示したときは、既存の休日を残したまま土日の休日行を補います。日付を押すと休日行が追加または削除されるため、土曜出勤や会社独自の休日を設定してから年度分をまとめて保存できます。従来の `date,is_holiday,description` 形式は読み込み時に休日行だけへ変換され、次回保存時に1列形式へ移行します。

`team_level` は `large`（大チーム）、`medium`（中チーム）、`small`（小チーム）のいずれかです。階層は最大3段で、小チームを所属の必須単位とします。大・中チームは省略できるため、`小`、`大→小`、`中→小`、`大→中→小`の構成を混在できます。大・中チームを登録した場合、その配下には小チームが1つ以上必要です。

管理画面で新しいチームを追加すると`team_id`は自動生成され、利用者による入力は不要です。同じ親の直下では同名チームを登録できませんが、親が異なる場合は同名を使用できます。チームの`sort_order`はツリーの上から順にアプリが自動設定し、画面では「上へ」「下へ」で並び替えます。所属ユーザーもチーム詳細の一覧で「上へ」「下へ」を使って`display_order`を設定できます。日報は上位組織から下位チームの順にチーム単位で表示し、同じ所属内ではこのユーザー順を使います。日報の個人フィルターも同じ順序で表示します。`is_active`は既存CSVとの互換性のため残しますが、アプリが常に`1`を設定します。ユーザーの`small_team_id`には小チームのIDだけを設定でき、`display_order`は整数です。

既存の `user_master.csv` に新しい列がない場合も読み込めます。新しい列がない既存ユーザーは、自分の日報入力を有効、雇用区分を正社員として扱います。先に共通マスター画面でチーム階層を作成し、各ユーザーへ小チームと表示順を割り当てて保存すると新形式へ移行します。`team_master.csv` がない従来環境では、所属未設定のまま従来の担当部下関係だけで表示されます。

`commenter_employee_ids`には、その組織を担当するユーザーの社員IDを表示順どおりにセミコロン区切りで保存します。管理画面のチーム管理で追加・解除・並び替えでき、設定した組織とその全下位組織に現在所属するメンバーを担当部下として自動算出します。日報のコメント列は、対象者のチーム設定、係設定、課設定の順で、それぞれに登録された担当者順に表示します。同じ担当者が複数階層にある場合は最初の1列だけ表示します。旧形式の `superior_rank` と `managed_team_ids` は読み込み時にこの形式へ変換され、次回保存時に廃止されます。

`can_input_own_report` は `1`（入力する）／`0`（入力しない）で、自分の日報入力を制御します。`0` のユーザーは本人の日報更新を行えず、日報画面の本人行と「自分」フィルタも表示しません。「全員」フィルタにも本人を含めません。画面表示設定の「個人」は他メンバーの個人ボタンを制御しますが、本人の日報入力が有効なユーザーの「自分」ボタンは常に表示します。`employment_type` は `regular`（正社員）／`temporary`（派遣社員）、`is_admin` は `1`（管理者）／`0`（一般ユーザー）で保存します。管理者に設定できるのは正社員だけです。

派遣社員の日報画面は本人の日報だけを対象とし、「自分」以外の課・係・チーム・全員・個人フィルターを表示しません。サーバー側でも本人以外の日報を取得できず、他ユーザーへのコメント更新も拒否します。

上司が「自分」を選ぶと本人の日報と、本人より上位の上司コメント列だけを表示します。「全員」および課・係・チームのフィルターでは本人の行を除きます。「全員」ではコメント対象として算出された担当部下だけを表示します。

日報の閲覧範囲は、ログイン中の本人、現在同じ小チームに所属するメンバー、現在のコメント対象組織から算出された担当部下の和集合です。過去の日報も現在の所属を基準に判定します。同じ小チームのメンバーには上司コメントと返信も表示されますが、コメントを編集できるのは現在そのメンバーを担当する上司だけです。従来の`superior_config.csv`は使用しません。

「未確認」は、設定した集計開始日から今日（設定により今日を除外）までの非休日について、ログイン中の上司が担当部下へコメントしていない日数です。日報本文が未入力の日も数えます。

```powershell
npm install
npx playwright install chromium
npm run test:ui
```

## WebViewセキュリティ検証

Windows上で非表示のWebView2を起動し、CSP下でもPythonブリッジが動作することと、外部URL・新規ウィンドウへの遷移が遮断されることを確認します。

```powershell
python .\tools\verify-webview-security.py
```

## 依存関係の更新

`pywebview`は、Windowsで検証したバージョンを`requirements.txt`へ完全固定します。更新時はバージョンを書き換えて再インストールし、Pythonテスト、UI検証、WebViewセキュリティ検証をすべて実行してください。検証せずに`>=`などの可変範囲へ戻さないでください。

## IME診断ログ

セル編集時のIMEイベントは、`logs/ime-diagnostics.jsonl`へ記録されます。入力内容、氏名、日付は記録せず、イベント順序、変換状態、フォーカス、文字数、選択位置、入力欄の高さだけを保存します。イベントはブラウザー内で一時的にバッファし、変換中にはPython側へ送信しません。ログは約1MBでローテーションし、直近3ファイルまで保持します。
